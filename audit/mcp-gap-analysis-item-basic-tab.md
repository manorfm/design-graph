# Análise MCP × modelo — aba Básico do editor de Item

Documento de investigação para otimizar o plugin MCP de design graph (`user-design-graph`).  
Não é spec de produto. É evidência de por que um modelo alinhou a aba **quatro vezes** e ainda deixou gaps de componentes.

**Captura ao vivo:** 2026-08-19 23:02 BRT  
**URL:** `http://localhost:5173/catalog/items` (editor overlay, item **Smash Duplo**, aba **Básico**)  
**Protótipo carregado:** `ipede_manager_v21.1`  
**Servidor MCP:** `user-design-graph`  
**HTML bruto:** seção final deste arquivo + `docs/agent-context/fixtures/`

---

## 1. Como usar este arquivo

Outro modelo deve ler nesta ordem:

1. **§3 Falhas do plugin** — o que consertar no MCP.
2. **§4 Log Q→A** — o que o modelo perguntou, o que voltou, o que ele inferiu errado.
3. **§5 Gaps reais** — verdade de tela (HTML ao vivo) vs JSX do protótipo.
4. **§8 HTML** — prova. Não reconstruir a aba só a partir de `get_component_spec`.

Pergunta que este caso responde:

> Por que `get_full_jsx('BasicTab')` + `get_component_spec('Chip'|'Segmented')` **não basta** para fechar paridade visual de uma aba que **não é uma Screen** no grafo?

## 3. Falhas do plugin (priorizadas)

### P0 — Telas que não são `Screen` ficam invisíveis para o fluxo “tela cheia”

`ItemEditorV6` **existe** como componente (`list-item`). `BasicTab` existe como `tab`.  
`list_screens` **não lista** o editor. `get_screen_full('ItemEditorV6')` retorna:

```
Screen 'ItemEditorV6' not found. Available: InventoryPage, RestaurantDetail, ClientItemDetail, ...
```

O modelo pede “a tela de detalhes inteira” e o MCP só oferece `ClientItemDetail` (ficha do **cliente**, `DietRow`) ou `ItemDetailDrawer` (estoque). Nenhum é o editor.

**Fix sugerido:** promover overlays/full-page editors a Screen, **ou** `get_screen_full` aceitar componente raiz com filhos + layout. Relacionar `CONTAINS` de verdade: hoje `BasicTab` “filhos” = `IconBtn, NumInput, SwitchRow, TextInput` — faltam `Card, Field, Segmented, Chip, Pill, TextArea, Sel, Btn`.

### P0 — `get_full_jsx` trunca o meio da aba e ainda diz “completo”

`get_full_jsx('BasicTab')` corta em:

```jsx
<K.Field label="Preparo"><K.NumInput value={si.prepTimeMinutes} on[handler]
```

Some: `onChange` sanitizado (`on[handler]`), Serve / Porção / Calorias, fechamento dos Cards. O título da ferramenta (“JSX completo”) induz o modelo a **parar**.

`get_component_spec('BasicTab')` também corta (`+5000 caracteres`) e manda chamar `get_full_jsx` — que **também** corta.

**Fix sugerido:** paginar (`offset`/`cursor`), ou emitir JSX por **Card/seção**, ou arquivo. Nunca rotular de completo se `on[handler]` ou `...` restarem.

### P0 — JSX do componente-folha também é sanitizado no ponto que o modelo precisa

`get_full_jsx('Segmented')` / spec:

```jsx
style={{ padding: o.icon && !o.label ?, fontSize: T.sm, fontWeight: 500, border: none, cursor: pointer, display: flex, ... }}
```

Estilos default extraídos:

| Propriedade | Valor extraído |
|-------------|----------------|
| background | `value === o.value ?`  (**ternário cortado**) |
| color | `C.faint \| value === o.value ?` |
| padding | `o.icon && !o.label ?` |
| borderRadius do track | `R.md` no JSX; token listado `radius_sm = 8` |

O modelo **inventou** selected = `#444` / `colors.border2` porque o MCP não devolveu o ramo `true` do ternário. Pode estar certo ou errado; **não é dado**.

**Fix sugerido:** avaliar ternários no estado default + selected/hover. Devolver `styles.default` e `styles.selected` **completos** (padding numérico, background hex).

### P0 — Spec de `Chip` atribui os estilos do **filho** (dot 7px) ao componente

Tabela “Estilos — default” do Chip:

| Propriedade | Valor |
|-------------|-------|
| width/height | 7 |
| borderRadius | 50% |
| background | color |

Isso é o `<span>` do `dot`, não o `<button>`. O JSX certo está **abaixo** da tabela. O modelo leu a tabela primeiro, concluiu que Chip “é um ponto”, e na tentativa 4 passou `dot` em Dietas / tags. No JSX do **BasicTab**, Chip **não** recebe `dot`:

```jsx
<K.Chip key={k} on={on} onClick={() => toggle('tags', k)} label={m.label} color={m.color} />
```

HTML ao vivo **tem** o span 7px. Gap **introduzido pelo MCP + modelo**, não pelo protótipo da aba.

**Fix sugerido:** estilos default = nó raiz. Filhos em `children[].styles`. Não promover o primeiro `span` interno a spec do componente.

### P1 — `search` é instável e AND de nomes falha

Nesta sessão:

| query | resultado |
|-------|-----------|
| `ItemEditor BasicTab ItemEditorV6` | `Nenhum resultado` |
| `Dietas` | UIText em BasicTab |
| `catálogo global` | `Nenhum resultado` (o aviso **não está** no protótipo — correto; o modelo não consegue **provar ausência** vs índice falho) |

Sessões anteriores a mesma query de nomes **achou** UIText. Índice não determinístico.

**Fix sugerido:** search OR por tokens; `exists:false` explícito vs zero hits por AND; não exigir as três strings no mesmo documento.

### P1 — Tokens extraídos com lixo de parser

`get_tokens(category=radius)`:

- `radius_8,` = `8,` (vírgula no nome e no valor)
- `radius_10,` = `10,`
- `radius_md` = `10` vs JSX `R.md` no Segmented vs `radius_sm = 8` na lista de tokens do mesmo componente

O modelo não sabe se a trilha do Segmented é 8 ou 10.

### P1 — Composição do editor some no JSX raiz

`get_full_jsx('ItemEditorV6')` troca as abas por:

```jsx
{[conditional:BasicTab]}
{[conditional:CompTab]}
...
```

Não há árvore montada. Pedir “tela inteira” devolve chrome (header 56px, grid `1fr 360px`, prévia) **sem** o conteúdo da aba.

`get_component_children('ItemEditorV6')` lista tabs, mas **não** `Tabs`, `Btn`, `ClientPreview`.

### P2 — Dual-graph ausente; HTML do protótipo inútil para grep

Policy do repo manda `graph_continue` → `graph_read`. Nenhum tool `graph_*` está registrado. O HTML packed não tem `BasicTab`. Única fonte = design graph sanitizado.

### P2 — `ClientItemDetail` vs editor

`DietRow` (cliente) ≠ bloco “COMO O CLIENTE VAI VER” do BasicTab (Pills `contém X`). Se o modelo “pede a tela de detalhes” e cai em `ClientItemDetail`, alinha a **prévia do app**, não os controles do editor.

## 6. Por que o modelo não fecha o loop

```
get_screen_full(editor)     → 404 (não é Screen)
get_full_jsx(editor)        → chrome + {[conditional:Tab]}
get_full_jsx(BasicTab)      → “completo” mas truncado
get_component_spec(Chip)    → estilos do filho
get_component_spec(Segmented) → selected cortado
get_component_children(aba) → 4 de ~12 filhos
search(nomes compostos)     → vazio
HTML packed do proto        → sem strings
código da app               → o modelo alinha o código a um spec incompleto
```

Falta no MCP:

1. **Árvore de tela** para overlays (editor = screen).
2. **JSX não truncado** (ou seções).
3. **Estilos por estado** no nó raiz.
4. **CONTAINS real**.
5. **Diff opcional** contra um snapshot HTML (o que este arquivo faz na mão).

Enquanto 1–3 não existirem, o modelo deve: (a) tratar `get_full_jsx` como parcial se houver `...` / `on[handler]` / `{[conditional`; (b) serializar a tela ao vivo; (c) não promover tabela “estilos default” acima do JSX raiz.

## 7. Recomendações concretas para o plugin

1. `list_screens` incluir `ItemEditorV6` (tipo overlay/fullpage).  
2. `get_screen_full` resolver `{[conditional:X]}` para o tab default (`BasicTab`).  
3. `get_full_jsx` falhar explícito se sanitização cortar, com `next_cursor`.  
4. Avaliar ternários: `styles.selected.background` hex.  
5. Spec visual = root node.  
6. CONTAINS: parse JSX de uso (`<K.Chip` dentro de BasicTab).  
7. Search: OR; `indexed=false` vs zero matches.  
8. Tokens: não criar labels `radius_8,`.  
9. Tool `get_usage_jsx(component, parent)` — Chip **como usado** em BasicTab (`dot` ausente).  
10. Opcional: `compare_html(name, liveHtml)` para o fluxo deste documento.
